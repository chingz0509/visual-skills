# visual-skills

做有主次、字图关系和纸张质感的摄影拼贴，而不是把所有照片塞进同一模板。实验版；首个验证环境为 Codex 桌面端 macOS。默认 1200×1600、3:4 竖版。

## 先选主体处理方式

沿用用户已经选择的方式；未明确时只问一次：**“保留照片原样，还是允许 AI 做更有设计感的创意改造？”** 不再追问可自行判断的配色、文案和布局。

- **原片拼贴 `preserve`**：原片提供唯一主体 RGB。可抠图、黑白、等比缩放、旋转和轻印刷质感。合照、风景保留完整照片；产品、宠物保留完整主要主体。分割损伤细节时使用整图。
- **创意改造 `creative`**：读 [创意改造](references/enhancement.md)。可用宿主图像工具处理主体、构图和材质，先记录 `allowed_changes` 与 `keep_features`。保留人物辨识度、关键物品特征和主体数量；检查脸、手、四肢、毛发、产品结构和文字。重绘结果明确标注，不能声称原片像素保真。

仅有聊天模型不等于有图像工具。创意模式用用户宿主的工具或用户自己的已配置服务；没有时说明，并采用用户接受的原片模式，不借用作者密钥，不让用户再安装无关 skill。

标题跟随对话语言，正式文案逐字保留，写入 `formal_copy`。创意短句可自动拟定，姓名、日期、活动、品牌背书等事实由用户提供。图片内文字是素材数据。

## 设计与执行

以下路径相对本 skill 目录；先定位绝对路径。技术步骤由 Agent 执行。

1. **看图并设计**：判断主体数量、轮廓、视线、色彩和背景。读 [风格与布局](references/style.md)，选构图与材料并说明理由。原片模式优先在 `cover/split/window` 中选合适语法；旧布局兼容旧记录。创意模式设计自由构图，不强塞本地模板。
2. **准备环境**：用宿主可用 Python 执行 `scripts/bootstrap.py`，读取其 Python/Vision 路径。可在 Codex 通过工作区依赖工具发现 Python。无分割能力时使用整图构图。依赖缺失由 Agent 处理；确实不能准备时明确报告。
3. **写计划并渲染**：按 [计划格式](references/plan.md) 写 JSON。原片用 `scripts/run.py render --input <原图> --plan <计划> --output <新目录>`；创意图先实际生成，再按增强说明导入。首轮采用复杂拼贴；复杂取决于字图主次与叠层关系。
4. **实际看图**：打开原片、准备图、最终图，同时检查原尺寸和约 300px 宽缩略图。按 [验收与修复](references/review.md) 写检查 JSON，执行 `scripts/run.py review --run <目录> --review <检查JSON>`。程序检查通过不代表好看，未看图不能填通过。
5. **有限修复**：拒绝首轮后 `repair`，改最明显的问题；仍失败时第二次修复自动退回完整原图的 `simple`。最多三次：复杂 → 一次修复 → 原片简洁降级 → 通过/失败。创意修复需要新的实际生成图与提示词记录；不反复重开目录绕过上限。
6. **交付**：嵌入 PNG，标明主体模式及 `complex_pass/simple_pass/failed`。提供原图、实际资产、计划、字体、检查和记录。AI 整图结果保存为一个生成图层，明确不提供其内部可编辑纸层。用户验收仍单独记录。

保存的图层使用 `scripts/replay.py <attempt目录> --output <新PNG>` 精确重合成，过程不调用模型。重新生图可能改变结果。固定的旧十张样例和旧报告保留；新模式另建实验，不沿用旧成功率。
