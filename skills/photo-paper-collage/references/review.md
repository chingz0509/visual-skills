# 验收与修复

程序硬指标与视觉检查互补。程序核对像素处理来源、整图类别约束、PNG 比例、图层边界、最低字号和正式文案字符串；它不能证明抠图完整，也不能决定美观。

每次打开原片、准备后的照片和最终成品。看到实际图片后，才写审查 JSON：

```json
{
  "reviewer": "当前 Agent 的名称",
  "subject_fidelity": true,
  "edge_integrity": true,
  "text_correct": true,
  "style_coherent": true,
  "composition_usable": true,
  "notes": "具体写明对照了哪些主体细节、文字和版式，并指出局限。"
}
```

- `subject_fidelity`：所有主要主体、脸、身份、物品标识、关系和空间内容是否保留。RGB 相同但遮罩删掉了胡须、表链或某个人，同样失败。
- `edge_integrity`：边缘是否有明显缺口、漏背景、断裂或不合理切断。整图模式检查边界和照片是否被遮盖。
- `text_correct`：正式文案准确，创意标题语义恰当，字形完整、可读、无乱码。OCR 是诊断数据，不能替代人工视觉判断，也不能自动覆盖文案。
- `style_coherent`：清楚主次、照片和纸层的关系、排字及统一印刷质感是否成立。不是数装饰数量。
- `composition_usable`：照片比例自然，主体不被文字/胶带遮挡，标题留白合理，成品可直接发布。

失败必须保留当前尝试和具体原因。初次复杂拼贴 → 第一次修复（仍复杂，可以恢复完整照片）→ 第二次修复（程序强制完整原图的 simple）→ 最终通过或失败。最多三次渲染。不要通过换一张输入图、重开一个同任务目录、把 false 改 true 来绕过限制。

最终状态：`complex_pass`（复杂拼贴通过）、`simple_pass`（简洁拼贴通过）、`failed`（失败）。`needs_review` 和 `needs_repair` 是中间态，不能当作成功交付。自动最终结果不等于项目发起人的首版最终验收。

## 首版实验门槛

调试前固定 10 张、五类各两张，一易一难。至少 8 张可直接用，且其中至少 6 张复杂拼贴通过；保真不合格一律不计入。简洁版只有五项全通过才计入。门槛尚不代表泛化能力；固定集调试是开发验证，不是独立盲测。完整展示通过、降级和失败（未发生的状态如实记 0）。
